# Contributing

Describe the channel, layout, observed status and reproduction steps. Do not attach tokens, private messages or unredacted personal paths. Contributions use GPL-3.0. Keep C# 5/.NET Framework 4.8, no NuGet, and focused modules.

Run `scripts\test.ps1`, `scripts\test-service.ps1`, `scripts\build.ps1`, `tests\PowerShell.Parse.Tests.ps1`, `tests\Setup.Contracts.Tests.ps1`, `tests\Setup.Ui.Tests.ps1`, and `tests\Package.Tests.ps1` in Windows PowerShell. Also run `tests\Service.Wts.Tests.ps1`, `tests\Countdown.Clock.Tests.ps1`, `tests\Worker.Startup.Tests.ps1`, `tests\Worker.Status.Tests.ps1`, and `tests\Status.Handoff.Tests.ps1` for exact result/consent/startup/UI-lifetime boundaries. Ordinary-user GUI changes also need the applicable `App`, `Worker`, `Countdown`, `Restart`, and `Shutdown.Smoke.Tests.ps1` fixtures. These portable tests own GUID LocalAppData roots and exact processes; never activate the developer's real Discord, default helper, startup, or services. An elevated worker smoke tests the rejection guard and explicitly skips ordinary-user repair/UI acceptance.

Before publishing a release, run `scripts\test-user.ps1` from a native Windows checkout in an ordinary, unlocked user session. It runs all 17 local build/test commands, rejects skipped coverage, checks that source files remain unchanged, and records the per-file source hashes, fingerprint and results under `artifacts/user-acceptance`. Test assemblies load by path; WSL UNC checkouts must be copied to a native local directory for this acceptance run. Retain the receipt with the release evidence. Hosted administrator CI is separate and does not replace ordinary-user acceptance. `artifacts\ServiceTests.exe --idle-probe 300` also measures sustained native broker idle after paced unrelated/log activity, without forcing garbage collection or touching the installed service; CI runs a 120-second sample.

Actual SCM testing is restricted to an isolated administrator GitHub Windows runner: `Setup.Tests.ps1`, `Setup.Safety.Tests.ps1`, `Setup.Recovery.Tests.ps1`, `Service.Scm.Tests.ps1` and `Package.Tests.ps1 -RequireAdmin`. Pass `-RequireAdmin` to **every** required SCM script. Without elevation they fail when required; ordinary local calls explicitly skip without claiming service coverage. Even elevated calls refuse outside GitHub Windows CI. Never elevate these tests on a developer desktop.

Machine fixture overrides must include exactly `-FixtureRoot`, `-Destination`, `-ServiceName` and `-ShortcutPath`. For a fresh lowercase 32-hex GUID, the only allowed values are native `%ProgramFiles%\VencordAutoUpdate.Tests\<guid>`, its `Application With Spaces` child, `VencordAutoUpdate-Test-<guid>`, and its `Status.lnk` child. Setup creates protected ACLs; user-writable ancestors, reparses, partial overrides and escaped names/paths are refused. No fixture user paths or command bypass exists in production SCM arguments or release assets. The separate SCM host is compiled from `tests/Service/ScmFixtureHost.cs` only for CI; its real notifications use a fixture launcher. Production SCM lifecycle, test-host notification coverage and actual WTS ordinary-user launch are separately reported. A hosted runner without an active unlocked eligible session leaves WTS launch **unverified**, not passing. Do not weaken identity checks to make a hosted test green.

Installer tests verify actual register/start/status/stop/unregister, protected ownership, foreign resource retention, exact configuration and bounded failure actions, mapped-file refusal, interruption rollback, and scoped cleanup. Failed shutdown or uncertain ownership must retain binaries/evidence. Cleanup only exact owned fixtures, preserve other processes and report retained files. Native own-process service naming under a GUID is tested in SCM, not inferred solely from API documentation.

Package with `scripts\package.ps1 -RequireClean`; tagged publication also requires `-RequireTag`. The ZIP contains both binaries, all seven setup scripts, five public documents and `SOURCE.txt`; `SHA256SUMS` covers the complete archive. CI and release use pinned actions. Verify effective Windows CI before tagging. Future real Discord updates and Vencord runtime settings-page injection remain manual acceptance limits.
