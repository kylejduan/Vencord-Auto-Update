# Vencord Auto Update

An independent community Windows helper that restores a recognized, locally installed Vencord loader after a Discord update replaces it. It does not download Vencord, Discord, plugins, or helper updates and is not affiliated with Discord or Vencord. Windows 10/11, ordinary per-user Discord Stable/PTB/Canary, and .NET Framework 4.8 are supported.

Install Vencord once with the [official installer](https://vencord.dev/download/) and launch Discord successfully first. A healthy, recognized local loader is the only seed. Unknown archives and unsupported layouts are refused.

## Install and use

Download `VencordAutoUpdate-0.1.0-windows.zip` and `SHA256SUMS` from the [release page](https://github.com/kylejduan/Vencord-Auto-Update/releases). Verify the ZIP's SHA-256, extract the entire ZIP, and open `VencordAutoUpdate.exe` normally. Choose **Install** and approve Windows UAC. The status window exits after setup starts. Setup copies both executables and the complete setup modules into native `%ProgramFiles%\VencordAutoUpdate`, registers and starts the automatic **VencordAutoUpdate** Windows service, and creates the common Start menu **Vencord Auto Update** shortcut. Command-line setup requires an administrator PowerShell running the extracted `install.ps1`.

The LocalSystem service is a narrow broker: it receives directory/session notifications and waits for relevant process exits. Healthy idle has no recurring scan, hashing loop, WMI subscription, or resident tray. It launches only its fixed adjacent worker under the active unlocked user's ordinary, non-elevated Windows token. The worker alone reads user policy and repairs files. No password is stored. Elevated or service-identity worker/UI launches are refused.

Open the Start menu shortcut for on-demand **Status / Setup**: pause repairs, disable automatic restarts, inspect channels, open logs, or request **Repair & Restart** with fresh confirmation. Closing Status exits that UI; the installed service continues protection. The service-facing worker returns after a healthy scan, completed work, deferral, or refusal, even if you open Status during that work. Its ordinary host exits too unless you explicitly keep Status open. A request temporarily uses an extra ordinary process; healthy idle adds no automatic resident. Work has a 180-second budget; an already-entered archive transaction drains safely. Locked/disconnected users wait for an eligible session.

## Repair and restart limits

Channels are classified independently. The helper caches a recognized local loader, validates Discord's original archive and local Vencord assets, and preserves the original instead of overwriting unknown content. Ambiguous or corrupt state, unknown loaders, differing originals, incomplete transactions, or exhausted history retain evidence and stop automatic repair.

An eligible recently started Discord session may show a visible **20-second restart countdown**, measured by elapsed time from when it opens. **Not now**, a locked desktop, disabled restarts, or an established session defers repair until full exit. Restart can interrupt calls or drafts. Automatic restarts are limited to one per generation and one globally per ten minutes; persisted attempt/cooldown limits survive service and worker restarts. Failed delayed verification prohibits more automatic restarts; a fresh confirmed manual repair still requires valid files.

Reactive repair cannot guarantee a patched first frame or first launch after every update. A deferred session can remain stock until a repaired restart. File validation does not prove Vencord injected: after a real update, confirm its settings page in Discord. Future Discord/Vencord changes may require a helper release or the official installer.

## Update, recovery, and uninstall

For helper updates, close Status in every user session, extract the new ZIP, and run its `install.ps1` in administrator PowerShell. Setup verifies the existing manifest, every owned file, service configuration/ACL and shortcut before stopping or replacing anything. It waits up to 240 seconds for orderly service shutdown and refuses mapped/in-use executables with close-Status guidance. If work is still draining, the service reports an overrun after 225 seconds and stays Stop Pending; retry setup after the work exits and the service stops. Windows system shutdown has a separate OS deadline that these waits cannot override. It never force-kills a repair to proceed. Successful setup starts protection immediately.

Verified old/new snapshots and an interrupted-operation record live under `%ProgramFiles%\VencordAutoUpdate.Setup\recovery`. Rerun install or uninstall from a complete extracted release after interruption: setup restores the previous verified installation before continuing. Unknown modified content, failed shutdown, or incomplete ownership proof blocks recovery and retains evidence. Incomplete `staging-*` or cleanup `completed-*` directories may remain for inspection; they are not active recovery. Machine setup serializes across administrators through a protected lock file. The service's crash policy permits three restarts at 60-second delays and ends with **no action**, resetting the failure count after a day without failure; this is separate from user repair/restart policy.

Choose **Uninstall** in ordinary Status, or run the extracted `uninstall.ps1` in administrator PowerShell. It removes only the verified machine service, shortcut and installed files. Protected foreign non-runtime neighbors remain; unowned DLL/config/executable sidecars or writable descendants block setup without being deleted. All users' state, cached loaders, logs and recovery evidence remain at their `%LOCALAPPDATA%\VencordAutoUpdate\data`; privileged setup never parses or removes that data. The small protected setup lock directory remains. There is no `-RemoveData` or legacy per-user task migration. Setup never changes Discord shortcuts, autostart, protocol handlers, or Vencord files.

## Diagnostics, source, and provenance

`VencordAutoUpdate.exe --status` is read-only and may run elevated without creating cache/state. `--worker` requests bounded ordinary-user work; its exact outcomes are 0 Done, 21 Refused, 22 Retry, or 65..71 deferred root masks (Stable 1 / PTB 2 / Canary 4 combined with 64). The broker waits only for those known roots, independently; hints grant no repair authority. `--worker-host` is the ordinary internal host candidate, which exits after five seconds without a request or manual interaction. `--stop` asks only the current user's exact default-data instance to drain and exit. No-argument launch opens Status; the retired `--run` switch is rejected.

Portable ordinary-user fixtures require paired `--data-dir C:\fixture\helper --discord-root C:\fixture\Discord`, optionally `--vencord-dist C:\fixture\Vencord\dist`. `--stop --data-dir C:\fixture\helper` addresses only that instance. The root must be named `Discord`, `DiscordPTB`, or `DiscordCanary`. Use one data directory per root set. Portable UI disables setup. Protected machine test overrides and the administrator CI gate are documented in [CONTRIBUTING.md](CONTRIBUTING.md); they are unrelated to worker portable paths.

Build with Windows PowerShell 5.1: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1`. This builds both C# 5/.NET Framework executables without NuGet or downloads. Releases are **unsigned**: verify the checksum and matching source tag before execution. `SOURCE.txt` identifies the version, source commit and clean/dirty build state. SHA-256 establishes byte integrity against the published checksum, not an independent publisher signature. See [CONTRIBUTING.md](CONTRIBUTING.md), [SECURITY.md](SECURITY.md), and [GNU GPL version 3](LICENSE). No telemetry or credentials are collected.
